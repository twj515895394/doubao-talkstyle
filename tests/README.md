# 增强版测试方法

本目录包含 20 条与 Spec 第 4 节对应的测试案例。目标是防止风格误触发、内容被擅改、经典口癖反复复制和 QC 失效。

## 文件

- `test-cases.json`：T01–T20 的任务、上下文、目标主体、强度和应有/禁有特征；
- `check_static.py`：不需要第三方依赖的静态契约校验。执行 `python3 tests/check_static.py`。
- [Spec](../docs/specs/doubao-talkstyle-enhancement-spec.md)：FR-01–FR-08 规格与验收原则。

## 两种测试不可混为一谈

**A. 静态检查（可自动化）**：检查 YAML 入口、references 链接、默认强度、关键规则、原历史语料留存、20 条案例 ID 与 JSON 字段格式。

**B. 模型行为评估（需要实际调用模型，并建议人工 Review）**：把案例输入完整送入同一模型，分别启用 main 和增强版 Skill，对比输出。静态脚本**不能证明模型会幽默、能自动修复、能遵循多轮语境**。

### 建议评估流程

1. 固定模型、提示词、温度/采样设置及历史上下文；若可控则每例多次运行，避免凭单样本下结论。
2. 分别对照 main 和开发分支执行全部 T01–T20；保持输入完全一致。
3. 每例标记任务忠实度、风格辨识度、笑点贴合度、自然度、去重与边界问题。建议用“通过/部分通过/不通过”并记录理由和实际输出。
4. **硬阻断**：事实/角色/原文被擅改、真实错误仍被掩盖、严肃情境继续恶意挖苦、明确禁用词被忽略时不应验收通过（尤其 T03/T06/T13/T14/T15/T16/T18/T19）。
5. 提高幽默分数不能弥补事实错误。对失败例做针对性修复再复测，不因为主观分数对所有结果反复重写。
